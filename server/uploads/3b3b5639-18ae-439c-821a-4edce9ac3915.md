# AI 低代码平台 - 项目说明文档

## 1. 项目概述

本项目是一个**企业级AI应用低代码平台**，旨在帮助企业和开发者快速构建AI应用，无需深入了解底层AI技术细节。平台提供可视化工作流编排、知识库管理、AI对话等核心能力，支持多租户、权限管理和API对接。

### 1.1 项目定位

| 维度         | 描述                                         |
| ------------ | -------------------------------------------- |
| **目标用户** | 企业开发者、业务人员、AI应用集成商           |
| **核心价值** | 降低AI应用开发门槛，快速构建智能化业务系统   |
| **应用场景** | 智能客服、知识库问答、自动化流程、数据分析等 |

## 3. 核心功能模块详解

### 3.1 可视化工作流编辑器

**给谁用：** DEVELOPER、ADMIN

**功能说明：**

- 拖拽式节点编排，支持多种节点类型
- 可视化连线和条件分支
- 实时预览和调试能力

**节点类型：**

| 节点类型      | 图标 | 功能描述                 |
| ------------- | ---- | ------------------------ |
| Start         | 🟢   | 工作流入口，初始化上下文 |
| End           | 🔴   | 工作流出口，返回结果     |
| UserInput     | 💬   | 接收用户输入内容         |
| SystemPrompt  | 📝   | 设置AI角色和系统提示词   |
| LLM           | 🤖   | 调用AI大模型生成响应     |
| KnowledgeBase | 📚   | 检索知识库相关信息       |
| Condition     | 🔀   | 条件判断，分支路由       |
| VariableSet   | ⚙️   | 设置流程变量             |

**使用场景：**

- 构建智能客服对话流程
- 设计自动化业务审批流程
- 创建多步骤AI分析流程

---

### 3.2 AI对话系统

**给谁用：** 所有角色

**功能说明：**

- 支持流式响应，实时显示AI回复
- 会话历史管理和收藏功能
- 多应用切换能力

**使用场景：**

- 用户与AI应用进行自然语言交互
- 基于知识库的问答查询
- 执行预设工作流获取结果

---

### 3.3 知识库管理

**给谁用：** DEVELOPER、ADMIN

**功能说明：**

- 支持多文档格式上传（PDF、Word、TXT）
- 自动文档分块和向量化
- 文档状态跟踪和重新处理

**技术流程：**

1. 上传文档 → 2. 文本提取 → 3. 分块处理 → 4. 向量化 → 5. 存储到向量数据库

**使用场景：**

- 企业内部知识沉淀和查询
- 产品文档智能问答
- 技术手册自动检索

---

### 3.4 RAG（检索增强生成）系统

**给谁用：** 底层能力，面向开发者

**功能说明：**

- 将用户问题与知识库匹配
- 获取相关知识片段作为AI上下文
- 提升回答准确性和相关性

**核心组件：**

- **文本分块服务**：智能切分长文本
- **多嵌入服务**：支持多种嵌入模型
- **RAG编排器**：协调检索和生成流程

---

### 3.5 OpenAI兼容API

**给谁用：** 外部系统集成商、开发者

**功能说明：**

- 提供与OpenAI API兼容的接口
- 支持标准的chat/completions格式
- 可作为代理服务整合多种AI模型

**API端点：**

```
POST /api/openai/chat/completions
```

**使用场景：**

- 第三方系统接入AI能力
- 迁移现有OpenAI应用到本平台
- 统一管理多种AI模型调用

## 4. 第三方对接能力

### 4.1 作为服务提供者（被对接）

**API接口类型：**

| 接口类别   | 端点前缀                     | 说明                   |
| ---------- | ---------------------------- | ---------------------- |
| OpenAI兼容 | `/api/openai/*`              | 提供标准OpenAI API接口 |
| 应用调用   | `/api/apps/{id}/execute`     | 执行指定应用工作流     |
| 知识库检索 | `/api/knowledge/{id}/search` | 搜索知识库内容         |
| 会话管理   | `/api/conversations/*`       | 管理对话会话           |

**认证方式：**

- **API Key认证**：通过 `X-API-Key` 请求头传递
- **JWT认证**：通过 `Authorization: Bearer {token}` 传递

**使用场景：**

- 企业内部系统集成AI能力
- 移动App接入AI服务
- 其他平台通过API调用本平台能力

### 4.2 作为服务消费者（对接第三方）

**第三方服务集成：**

| 服务类型       | 集成方式              | 用途               |
| -------------- | --------------------- | ------------------ |
| **AI模型**     | OpenAI SDK、自定义API | 调用外部大模型     |
| **邮件服务**   | Nodemailer + SMTP     | 发送密码重置邮件   |
| **向量数据库** | pgvector              | 存储和检索向量数据 |
| **缓存服务**   | Redis                 | 限流、会话缓存     |

**开发/生产环境切换：**

| 环境 | 邮件服务              | AI模型         |
| ---- | --------------------- | -------------- |
| 开发 | Ethereal（测试邮件）  | 可配置测试模型 |
| 生产 | SendGrid/阿里云邮件等 | 正式AI服务     |

## 5. 典型使用场景

### 场景1：企业智能客服

**角色：** DEVELOPER 创建应用，USER 使用应用

**流程：**

1. 开发者创建"智能客服"应用
2. 设计工作流：用户输入 → 知识库检索 → LLM回复
3. 上传产品文档到知识库
4. 用户通过对话界面咨询产品问题
5. 系统自动检索相关知识并生成回答

### 场景2：API服务集成

**角色：** 第三方开发者

**流程：**

1. 在平台创建应用并设计工作流
2. 生成API Key
3. 第三方系统通过 `/api/openai/chat/completions` 调用
4. 平台执行工作流并返回结果

### 场景3：内部知识管理

**角色：** ADMIN/DEVELOPER

**流程：**

1. 创建知识库并上传文档
2. 配置权限允许员工访问
3. 员工通过对话界面查询知识
4. 管理员查看使用统计和效果分析

### 场景4：自动化审批流程

**角色：** DEVELOPER

**流程：**

1. 设计审批工作流：开始 → 用户输入 → 条件判断 → LLM分析 → 结束
2. 配置条件分支（金额>1万需多级审批）
3. 测试并发布应用
4. 用户发起审批请求，系统自动处理

## 6. 项目部署与集成

### 6.1 部署方式

| 方式               | 说明             | 适用场景           |
| ------------------ | ---------------- | ------------------ |
| **Docker Compose** | 一键启动所有服务 | 本地开发、测试环境 |
| **Kubernetes**     | 容器编排部署     | 生产环境、高可用   |
| **云服务商**       | Railway/Render等 | 快速上线、托管部署 |

### 6.2 环境变量配置

**核心配置项：**

| 变量名           | 说明               | 示例值                                     |
| ---------------- | ------------------ | ------------------------------------------ |
| `DATABASE_URL`   | PostgreSQL连接地址 | `postgresql://user:pass@localhost:5432/db` |
| `REDIS_URL`      | Redis连接地址      | `redis://localhost:6379`                   |
| `JWT_SECRET`     | JWT密钥            | `your-super-secret-key`                    |
| `OPENAI_API_KEY` | OpenAI API密钥     | `sk-xxxxxxxxxx`                            |
| `MAIL_HOST`      | 邮件服务器地址     | `smtp.sendgrid.net`                        |

### 6.3 安全建议

1. **生产环境**：使用真实邮件服务，配置正确的SMTP参数
2. **密钥管理**：使用环境变量或密钥管理服务，不要硬编码
3. **访问控制**：限制API访问IP白名单
4. **日志审计**：开启审计日志，定期检查异常操作
